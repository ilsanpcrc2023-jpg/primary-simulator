## 1. 목표와 범위

노션 보고용 문서(@BH, 2026-04-18)의 "환자군(NHIS-HCC) 기반 일차의료 지불모형"을 시뮬레이터에 반영. 핵심 확장:

1. **주치의 등록관리비 (R)** — 환자군 기본수가 P 위에 구조적으로 합쳐지는 지속 수가
2. **등록환자 규모 파라미터** — 의원 수(M), 의원당 등록환자수(n_reg), 환자군별 등록률(k_g)
3. **혼합 수입 수식** — 등록환자는 환자군 모형, 비등록환자는 FFS 유지
4. **용어·표기 정비** — PP, A, L, N, M 등 기호 일관 적용

범위 밖 (의도적 제외):
- 일차의료 전환지원금(PT) — 복지부 예산 산정용이라 시뮬레이터 불필요
- 환자유형군 vs HCC군 UI 분리 — 시뮬레이터는 HCC군만 필요
- localStorage 영속화 — 시연 안정성 우선, phase 2로 유예

## 4. 핵심 수식 (변경 금지)

```
P     = 환자군 기준의료비 × 의원급 외래비중         (빅데이터 산출)
PP    = P + R                                     (명목 청구수가)
A     = P × (1 − L) + R                            (공단 실지급, R은 L 우회)
B     = M1 × 30%                                   (본인부담, 고정)
의원 수입 = A + B  (등록환자)  +  M1  (비등록환자)

Track (1인당 등록환자 기준):
  tA = M1 + R                                     (Track A: FFS + R)
  tC = P × (1 − L_new) + M1 × 0.3 + R              (Track C: 환자군 모형)
  tB = (tA + tC) / 2                              (혼합 50:50)
  tS = tA × ffsPct + tC × hccPct                   (선택)
```

공단 서버 이관 시 위 수식을 그대로 SQL/스크립트로 옮기면 됨. `src/hooks/useSimulator.js`의 G useMemo 참조.

## 7. 개념적 주의 사항 (공단 서버 이관 대비)

### ⚠ PP ≠ 공단 실지급
PP = P + R은 **명목 청구수가**. 공단이 의원에 실제 주는 돈은 A = P × (1 − L) + R. L이 0.8 수준(파일럿)이면 PP와 A의 차이가 매우 크다. 이 구분을 놓치면 재정 추정이 틀어짐.

### ⚠ R은 L 우회
R은 "등록 관리 업무"에 대한 대가이지 진료비 재배분이 아니므로 타원이용비중 L에 걸리지 않는다. 등록환자가 타의원을 많이 이용해도 R은 등록의원이 전액 받는다. 이는 Track A에서도 R 효과가 나타나는 근거이며, 노션 Q6의 "수입 감소 없음" 보장의 핵심.

### ⚠ 등록환자 ≠ 이용환자
- **이용환자 N** (실인원) = 해당 의원을 1년간 이용한 환자 전체
- **등록환자** = 주치의 등록 동의한 일부 (의원당 n_reg명, 기본 1,000)
- **비등록환자** = N − 등록환자. 기존 FFS로 진료받음. Track과 무관.

파일럿 데이터(10개 의원, 69,604명)는 "이용환자 전체"의 평균. 등록환자 1,000명 제한 시나리오는 시뮬레이터가 비율 조정하여 계산.

### ⚠ 입력 모델: 의원당 실인원 primary
현재 UX에서는 **의원당 실인원**이 primary 입력이고, totalN은 `의원당 × M`으로 파생. M 변경 시 의원당 값이 보존되고 totalN이 자동 스케일. 이는 공단 서버 이관 시에도 동일 모델을 따르는 것이 바람직 (임상의가 "우리 의원 환자 X명" 수준에서 사고하는 것과 일치).

### ⚠ KPI 제목 정확성
파랑 KPI 카드는 **"의원급 외래 의료비 변화"**이지 "공단 총의료비 변화"가 아님. 대상 범위 = 전원 FFS 기준 의원급 외래 총액 (입원·약국·병원급 제외). 보고·시연에서 "총의료비"로 표현하지 말 것.
