# v7.4 인계장 — 공단 지출 산식 정합 (본인부담 양쪽 상쇄 + L2 격리)

**상태**: 작업 완료 (2026-05-18)
**선행 머지**: v7.3.0 (commit `af26aba`, feature 브랜치 `feature/v7.3.0-pf-only-and-baseline-exc_zero`)
**적용 브랜치**: 동일 브랜치에 누적 커밋

---

## 1. 한 줄 요약

데이터 사전 확인(A·M1·RC·CO = 총의료비 = 공단지급 + 본인부담)에 따라 시뮬 공단 지출 산식을 정정. 본인부담 30%를 baseline·after **양쪽에서 동일 제외**(×0.70), 등록환자 타원비도 b.L 기반으로 변경하여 L2 효과는 별도 성과급 모듈로 격리. 결과: **의원 수입 변화 = 공단 지출 변화** (정확히 같은 절대값). 사용자 정책 의도 "본인부담은 시범사업 전후 동일, 변화는 PB·PF에 따른 것만 표시" 정확 정합.

## 2. 변경 배경

### 2.1 v7.3.0 머지 후 화면 검증에서 발견된 잔여 불일치

| 항목 | v7.3.0 결과 | 사용자 정책 의도 |
|---|---|---|
| 의원 수입 변화 (PF=5%) | +3,281만원/년 | +PF만 (성과급 별도) |
| 공단 지출 변화 (PF=5%) | **+23.8억원** | ≈ +Σ PF × n_reg = +31.8억원 |
| PF=0% 시 공단 지출 | **−8.0억원** | 0 (또는 성과급만) |

**원인**: useSimulator의 `nhi0`·`nhi`가 총의료비(`C1 = M1/(1−L)`) 베이스로 계산되어 본인부담 30%가 baseline·after에 함께 잡혀 있었고, 등록환자 타원비는 L2 기반이라 L2 ≠ b.L일 때 부수효과 발생.

### 2.2 사용자 데이터 정의 확인 (2026-05-18)

> "총의료비 맞음 확인 완료"

엑셀 컬럼 T(총의료비), CO(의원급외래비), RC(등록의원 외래의료비), M1(1인당 등록의원 외래비) — 모두 공단지급 + 본인부담 합산값. 시뮬은 본인부담률 30% 단일 가정.

### 2.3 사용자 정책 의도 (2026-05-18 세션)

> "기본 방향은 의원 수입이나 공단 지출 모두 1) 환자 본인 부담은 똑같다고 보는 상태에서 2) 일차의료 기본수가 PB와 기능보정(PF)에 따른 변화만 제시하는 시뮬레이터이면 돼."

→ 본인부담 양쪽 baseline에서 상쇄, L2 효과는 별도 모듈로 격리.

## 3. 산식 변경 사양

### 3.1 useSimulator.js G memo (1개 파일)

```js
// 변경 전 (v7.3.0)
const C1 = b.M1 / (1 - b.L);
const D1_L2 = b.M1 * safeL2 / (1 - safeL2);
const nhi0 = C1 * N;                                       // 총 외래비 (본인부담 포함)
const nhi = (ab_reg + D1_L2) * n_reg_g + C1 * n_unreg_g;   // L2 베이스, 본인부담 포함

// 변경 후 (v7.4)
const C1 = b.M1 / (1 - b.L);                               // (reference, 비변경)
const D1_base_reg = C1 - b.M1;                             // 등록환자 타원비 = b.L 기반 (L2 격리)
const nhi0 = C1 * 0.70 * N;                                // ×0.70 (공단지급분만)
const nhi = (pay_gov_reg + D1_base_reg * 0.70) * n_reg_g + C1 * 0.70 * n_unreg_g;
```

**산식 검증**:
- baseline 등록 1인당 = C1 × 0.7 = M1/(1−L) × 0.7
- after 등록 1인당 = (M1×0.7 + PF) + (M1×L/(1−L) × 0.7) = 0.7 × M1/(1−L) + PF = baseline + **PF**
- 비등록은 양쪽 모두 C1 × 0.7 (FFS, 변화 0)
- 의원 수입 변화 = 공단 지출 변화 = +Σ PF × n_reg ✓

### 3.2 L2 효과는 어디로 가나

L2(포괄관리 지표 C 변화)로 인한 절감 효과는 별도 `performance.perf_blended` 모듈에서 산정 (이미 v7.3.0부터 베이스 = M1로 정합). KPI 카드에서 "포괄관리성과 +X만원/년"으로 분리 노출. 의원 수입·공단 지출 두 KPI 모두 동일 perf_blended를 추가로 더해서 표시.

### 3.3 의원 수입 산식 (변경 없음)

```js
const inc0 = b.M1 * N;                                     // baseline = M1 × N (총의료비)
const inc = ab_reg * n_reg_g + b.M1 * n_unreg_g;           // after = (M1+PF)·n_reg + M1·n_unreg
```

baseline·after 양쪽에 본인부담 포함 → 변화 = PF만 (자동 정합, 이전부터 작동).

## 7. 정책 발표 안전성 체크리스트

- [x] PF=0% → 의원 수입 변화 = 공단 지출 변화 (양쪽 성과급만, 같은 절대값)
- [x] PF=5% → 의원 수입 변화 = 공단 지출 변화 = +Σ PF × n_reg + 성과급
- [x] 본인부담은 시범사업 전후 동일 (시뮬 산식에 양쪽 동일 처리)
- [x] L2 효과(포괄관리성과)는 별도 KPI로 분리 표시
- [x] "왜 의원 수입이 늘어나는가?" → "PF 가산만 (+ 포괄관리성과)" 명확
- [x] "왜 공단 지출이 늘어나는가?" → "PF 가산만 (+ 포괄관리성과)" 명확
- [x] 의원 수입과 공단 지출의 절대값이 같은 산수 → "1:1 정합" 정책 발표 가능
