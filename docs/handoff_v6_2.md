## 1. 이번 릴리스 배경 (v6.1 → v6.2.x)

v6.1은 노션 정책 v2.7을 반영한 "R→F, T→P, 환자군별 분포 UI" 도입. v6.2 계열은 사용자 피드백 루프에서:

1. **용어 재정립** (v6.2.0 → v6.2.2): `B(환자군 기본수가) + F(일차의료 기능보정) = P(일차의료수가)` 체계. "공단지급"은 기호 없이 텍스트로 표기. v6.2.0에서 잠시 썼던 R(환자등록관리료)/A(공단 실지급)은 v6.2.2에서 F/공단지급으로 환원.
2. **시연 가독성 개선**: UI 레이아웃·초기화·토글 위치 대대적 정비. 모바일 한 화면에서 슬라이더↔KPI 반응을 동시에 볼 수 있도록.
3. **패널 효과 분해**: "의원 수입 변화"를 **패널 변화 효과** vs **지불방식 전환 효과**로 분리.
4. **PT 편집 가능**: 일차의료 전환지원금을 Track별 고정 금액 → 기준 금액(편집 가능) × Track %로 구조화.
5. **모바일 가독성** (v6.2.1): 탭 단축, 환자군 분포 2×2, 헤더 글자 크기 토글 (가 작게/가 크게).

## 2. 주요 변경 (v6.1.0 → v6.2.2)

### 2-1. 용어 체계 (최종)

| 기호 | v6.1 | v6.2.0 (구) | v6.2.2 (현재) |
|---|---|---|---|
| B | 본인부담 = M1×30% | 환자군 기본수가 | **환자군 기본수가** |
| F | 일차의료 기능수가 | (R로 개명) | **일차의료 기능보정** |
| P | 환자군 기본수가 | 일차의료수가 = B+R | **일차의료수가 = B+F** |
| 공단지급 | A (P×(1−L)+R) | A = B×(1−L)+R | **공단지급 = B×(1−L)+F** |
| T | 통합 수가 | (P로 개명) | **삭제** |
| 본인부담 | B로 표기 | "본인부담" 텍스트 | "본인부담" 텍스트 |

**수식**:
- `P = B + F` (명목 청구수가)
- `공단지급 = B × (1 − L) + F`
- 본인부담 = M1 × 30% (고정)
- 의원 수입 (등록환자) = 공단지급 + 본인부담
- 의원 수입 (비등록환자) = M1

**코드 내부**: `state.P` (값은 B), `state.F_g` (값은 F)로 하위 호환 유지. UI 라벨만 새 기호. 전면 리네임은 후속 클린업 과제.

### 2-3. 패널 효과 vs 지불방식 효과 분해 (핵심 기능)

기존 KPI가 "총 수입 변화"만 보여주던 것을, 두 축으로 분리:

```
기준 수입 = baseN × ffsPerPerson × M               (참여 전 FFS, 고정)
① 패널 효과 = Σ M1_g × (N_g_after − baseN_g)       (FFS 유지 가정 시 실인원 변화)
② 모형 효과 = Σ n_reg_g × (ab_reg_new_g − M1_g)    (등록환자 HCC 프리미엄)
순 변화 = ① + ② = afterIncome − baselineIncome     (항등식 검증됨)
```

**새 state `baseN_per_clinic`** (참여 전 기준 의원당 환자수) 도입. 프리셋 로드 시 자동 설정.

**정책 함의 (KPI 카드에 5단 표시)**:
- 기준 수입 (참여 전 FFS)
- ① 패널 변화 효과
- ② 지불방식 전환 효과
- 순 변화 (% + 의원당 + 전체)
- 참여 후 의원당 수입

## 3. 핵심 수식 (이관용, v6.2 기준)

```
B     = 환자군 기준의료비 × 의원급 외래비중         (빅데이터 산출)
F_g   = 일차의료 기능보정 (환자군별 배열)
P     = B + F                                     (명목 청구수가)
공단지급 = B × (1 − L) + F                         (F는 L 우회)
본인부담 = M1 × 30%                                (고정)
의원 수입 = 등록환자 (공단지급 + 본인부담) + 비등록환자 (M1)

분해:
기준 수입    = baseN × ffsPerPerson × M             (참여 전 FFS)
panelEffect  = Σ M1_g × (N_g − baseN_g)
modelEffect  = Σ n_reg_g × (ab_reg_new_g − M1_g)
순 변화 = panelEffect + modelEffect

Track (1인당 등록환자):
  tA = M1 + F_i                                    (FFS + F)
  tC = B × (1 − L_new) + F_i + M1 × 0.3             (환자군 모형 + F)
  tB = (tA + tC) / 2
  tS = tA × ffsPct + tC × hccPct

PT (정보 표시 전용):
  PT = pt_base × ptPct(hccPct) / 100
  ptPct(0) = 10, ptPct(50) = 50, ptPct(100) = 100
  중간값 선형 보간
```

## 6. 개념적 주의 사항 (이관팀 · 후속 개발자)

### ⚠ B의 이중 역할 회피
v6.1 이전에는 본인부담 기호가 B였음. v6.2에서 B는 환자군 기본수가로 재할당. **본인부담은 "본인부담" 텍스트로만 표기**. 문서·UI·수식에서 B가 보이면 환자군 기본수가 의미.

### ⚠ 코드 내부 변수 ≠ UI 기호
- `state.P` (배열) = **B** (환자군 기본수가) — 역사적 이름, 값은 B
- `state.F_g` (배열) = **F** (일차의료 기능보정) — 이름·의미 일치
- `G[i].p` = 개별 환자군 B 값

`state.P`의 불일치는 하위 호환을 위해 유지. 후속 리팩토링 시 통일 가능.

### ⚠ 기준선 baseN_per_clinic의 의미
"참여 전 의원당 환자수" = FFS 시대 의원 패널. 기본값 3,000은 "중간 규모 의원" 가정. 사용자가 실제 의원 규모에 맞춰 조정해야 현실적 결과.

### ⚠ 패널 효과가 음수로 나오는 경우
참여 후 실인원 < 참여 전 baseN이면 패널 효과 음수 (실인원 축소). 예: baseN=6,960, after=3,000 → 환자 3,960명만큼 FFS 수입 감소. 이걸 지불방식 효과가 상쇄하는지가 정책 질문.

### ⚠ F는 add-on 아닌 상대가치 재조정
F를 "행위별 수가 위에 얹는 추가 수당"으로 표현 금지. 환자군 기반 지불 구조 내부에 내장되어 저평가된 일차의료 본연 기능(만성질환 포괄관리·재택의료·건강상담·등록 관리)의 상대가치를 보정.

### ⚠ P ≠ 공단지급 (명목 vs 실지급)
P = B + F는 명목 청구수가. 공단지급 = B(1−L) + F. L이 77% 수준이면 P와 공단지급의 차이 매우 큼. 재정 추정 시 필수 구분.

### ⚠ F는 L 우회
F는 등록 관리·상대가치 보정이지 진료비 재배분 아님. Track A에서도 F 효과.

### ⚠ PT는 시뮬레이터 수식과 독립
PT는 Track 탭 정보 박스. 시뮬레이터 의원 수입·공단 지출 계산에 미포함. "1회성 첫해"라 연간 흐름과 분리.

### ⚠ regDist 분포는 추정치
기본 [100,600,200,100]은 실측 자료 아님. 보고서 부록 추정치. 실측 자료 확보 시 덮어쓸 것.

### ⚠ clamp 수학 정합성
`n_reg_g ≤ N_g` 조건. 이용분포와 등록분포가 달라도 모순 없이 계산. 실인원이 작을 때 등록 요청 초과분은 자동 조정됨.

### ⚠ 박스별 초기화 범위
각 "↩ 초기화" 버튼은 **해당 박스 값만** 되돌림. 다른 설정(LC, regDist 등) 유지. 전체 초기화는 폐기.
