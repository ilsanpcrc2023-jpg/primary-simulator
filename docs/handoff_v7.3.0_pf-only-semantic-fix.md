## 0. 한 줄 요약

시뮬레이터의 모형 적용 효과(등록환자가 FFS → 환자군 모형으로 전환되며 발생하는 의원 수입 변화)를 **PF 가산만**으로 정정. 현재(v7.2.2)는 PB 전환 효과(B(1−L1) vs M1×0.7 차이 = 데이터 베이스 NT vs NC 비대칭에서 옴) + PF + 본인부담 합쳐서 발생 → **PF=0%여도 의원 수입 +1,312만원/의원당** 노출. 정책 발표 시 "왜 PF 없이도 의원 수입이 늘어나는가?"라는 시민단체·언론 비판 위험. v7.3.0에서 산식을 사용자 정책 의도("환자 본인부담 변화 없음, 의원 받는 돈 변화 없음, 변화는 PF만")에 정합시킴.

## 1. 변경 배경

### 1.1 사용자 정책 의도 (2026-05-09 세션)

> "환자 본인부담은 시범사업 전이나 후 변화가 없는거야. 환자 내는 돈도 똑같고, 의원 받는 돈도 똑같아. ... 모형 적용에 따른 변화는 PF 밖에 없어."

> "정리하면 PF만큼만 의원 수입이 느는 것이고."

> "1,312만원이 PF 늘리지 않아도 더 받는다는 것이지. 이렇게 바꾸면? 그런데 왜 라는 질문이 나오면 뭐라고 이야기하지?"

### 1.3 사용자가 든 정책 발표 시 우려

- "왜 PF=0인데 의원 수입이 늘어나는가?"라는 질문에 **데이터 베이스 차이**로 설명하면 비전문가에게 "데이터 보정으로 의원이 받는 돈이 늘어난다"로 들림
- 시민단체 시각: "PF 없이도 의원 수입이 자동 증가하는 구조" → **새 수가체계가 의사 수입 증가 도구라는 프레임으로 비판 가능**
- 정치 리스크 (v7.0에서 절대값/% 노출 차단했던 것과 같은 맥락)

### 1.4 v7.3.0 정책 의도

```
PF=0%일 때 의원 수입 변화 = +0원 (구조 전환만으로는 변화 없음)
PF=5%일 때 의원 수입 변화 = +PF × n_reg = +27,736 × 1,000 = +2,774만원/의원당
```

→ "왜 의원 수입이 증가하는가?" → "**일차의료 기능보정(등록관리·포괄진료) 가산만큼이다**"로 명확하게 답변.
→ 시민단체 비판 차단: "지불 구조 전환 자체로는 의원 수입 변동 없음, PF만 정책적 가산".

## 3. 산식 변경 사양

### 3.1 핵심 산식 (3가지)

#### (1) PB 정의 변경

```js
// 현재 (v7.2.2)
const pay_gov = p * (1 - L1_g) + F_i;   // p = state.P (B value), PB = B(1−L1)

// 변경 (v7.3.0)
const pay_gov = b.M1 * 0.70 + F_i;      // PB = M1 × 0.7 (공단지급분)
```

검증:
- 1군 PB(현재) = 58,558 → PB(v7.3.0) = 99,879 × 0.7 = **69,915원**
- 2군 PB(현재) = 80,824 → PB(v7.3.0) = 112,401 × 0.7 = 78,681원
- 3군 PB(현재) = 140,353 → PB(v7.3.0) = 177,477 × 0.7 = 124,234원
- 4군 PB(현재) = 233,787 → PB(v7.3.0) = 301,739 × 0.7 = 211,217원

#### (2) ab_reg (등록환자 1인당 의원 수입) 자동 정합

```js
// 변경 후 자동
const ab_reg = pay_gov + b.M1 * 0.30;
            = (b.M1 * 0.70 + F_i) + b.M1 * 0.30
            = b.M1 + F_i;                          // ★ 의원 수입 = M1 + PF
```

baseline (FFS) = M1, after = M1 + PF → **delta = PF** ✓ 사용자 정책 의도 정확 일치.

#### (3) 성과급 산식 (사용자 결정: 베이스 = M1)

```js
// 현재 (v7.2.2)
perf_raw_total += diff * r.p * r.n_reg;   // diff = max(0, L1 − L2), r.p = B

// 변경 (v7.3.0)
perf_raw_total += diff * r.b.M1 * r.n_reg;   // 베이스 = M1
```

성과급 의미: 등록환자가 등록의원 외래로 더 집중(L2 < L1 또는 C2 > C1)할 때 그 절감분을 의원에 환원. 베이스 M1 = 등록의원 외래 1인당.

UI 명명: 내부 변수 L1·L2 그대로 유지 (성과급 산식·데이터 동기화 정합성 유지). UI 표기만 C1·C2로 통일 검토 (v7.0에서 이미 "포괄관리 지표 C" 도입됨, 추가 작업 불요).

### 3.2 A·CR·B·L1·C1·PB → reference 강등

시뮬 엔진 핵심 변수: **M1, regDist (RR), PF, L1, L2** (5개)
시뮬 엔진 미사용 (reference): A, CR, B, C1, PB(=B×C1)

**예외**: L1은 성과급 산식 (max(0, L1−L2))에서 여전히 사용. UI 표기는 C1=1−L1로 통일하되 내부 L1 변수 유지.

PB 카드 NumBox는 산출값 표시(편집 불가) 또는 M1 직접 표시. PBtoB·calcPB는 reference 검산용으로만 유지 (또는 deprecated 처리).

## 5. 검증 계획

### 5.1 단위 테스트 회귀값 갱신 항목

- `pay_gov` 산식: B(1−L1) + F → M1×0.7 + F
- 의원 수입 변화 KPI: PB 전환 효과 제거 후 PF만 반영
- 회귀 방지 테스트 신규: `PF=0%일 때 의원 수입 변화 = 0` (사용자 정책 의도 핵심)
- 회귀 방지 테스트 신규: `PF=5%, 의원당 등록 1,000명일 때 의원 수입 변화 = PF × n_reg ≈ 27,736 × 1,000 = 27,736,000원/의원당` (소수 라운딩 ±10원)
- 성과급 베이스 검증: B → M1

### 5.2 브라우저 검증 시나리오

1. **PF=0% 시나리오**:
   - 의원 수입 변화 = +0원 ← 핵심 검증
   - 공단 지출 변화 = 0 (또는 미세 라운딩)
2. **PF=5% (디폴트) 시나리오**:
   - 의원 수입 변화 = 약 +2,774만원/의원당
   - 공단 지출 변화 = +27.7억/사업 전체
3. **C 슬라이더 조작 (포괄관리 지표 +5%p)**:
   - 성과급 발생 (M1 × ΔC × n_reg × TrackMul)
   - Track A=0, B=0.5, C=1.0 배수 정합

### 5.3 정책 발표 안전성 체크리스트

- [ ] PF=0%로 설정 시 의원 수입 변화 = 0 (스크린샷 확보)

## 6. 알려진 제한 / 의사결정 필요 사항

### 6.1 PB 카드 처리 방향 (선택 필요)

- **(가) PB 카드 유지, 산출값을 M1×0.7로 변경**: 가장 작은 변경. NumBox 편집은 불가능 (산출값) 또는 M1 직접 편집으로 변경.
- **(나) PB 카드 라벨 변경**: "환자군 위험도(HCC) 기반" 배지를 "M1 기반 (등록의원 외래 실측)"으로 갱신. PB의 의미가 본질적으로 바뀜.
- **(다) PB 카드 단순화 / 삭제**: PB가 단지 M1×0.7이라면 별도 카드 불필요. 데이터 관리 카드 reference로 강등.

→ **권고: (가)** — 시각적 변경 최소화, 사용자가 산출 근거 추적 가능.

### 6.2 상세 편집 테이블의 B·C1·PB 컬럼

- **(가) 그대로 유지 (reference)**: B = A×CR, C1 = 1−L1, PB = B×C1 산출 표시. 편집 안 됨.
- **(나) 두 번째 PB 컬럼 추가**: "PB(시뮬) = M1×0.7" 별도 컬럼 신설, 기존 PB(B×C1)와 병기.
- **(다) PB 컬럼 정의 변경**: PB = M1×0.7로 변경, B×C1은 부제로 작게.

→ **권고: (다)** — 시뮬 사용 값을 PB로 표시하고 산식 reference는 부제로.

### 6.3 성과급 베이스 (사용자 결정 완료)

- 베이스 = **M1** (사용자 결정 "M1으로 하고")
- C2 − C1 의미는 v7.0의 포괄관리 지표 C 카드와 자연 정합 (max(0, L1−L2) = max(0, C2−C1))
- UI 명명 통일: 내부 L1·L2 유지 (코드 일관성), UI는 v7.0의 C 카드 라벨 그대로

### 6.4 v7.0의 정치 리스크 차단 원칙

- 의원 총수입 절대값 노출 금지, 변화율 % 텍스트 차단은 **그대로 유지**
- v7.3.0은 시뮬 산식 정정만, KPI 노출 형식 (변화액 단독 hero)은 변경 없음
