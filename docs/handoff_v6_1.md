## 1. 이번 릴리스 배경 · 범위

2026-04-18 노션 「일차의료 시범사업 지불체계 보완 방안 v2.7」(임준 보좌관 보고용)이 v2.6 대비 두 가지 개념을 재정의:

## 3. 핵심 변경 (v6.0.0 → v6.1.0)

### 3-1. 용어·수식

| 항목 | v6.0 | v6.1 |
|---|---|---|
| R (주치의 등록관리비) | 단순 업무 수당, 균등 1만원 기본 | → **F (일차의료 기능수가)**, 환자군별 차등 공식안 |
| PP (최종 일차의료수가) | P + R | → **T (통합 수가)** = P + F |
| A (공단 실지급) | P × (1−L) + R | P × (1−L) + **F** |
| F 디폴트 | (R 균등 1만원) | 복지부 공식안 [122860/203040/291120/362530] (1:1.65:2.37:2.95) |
| k_g (등록률 조정계수) | 고급 아코디언 | **제거** (regDist로 대체) |
| regDist | 없음 | 의원당 환자군별 절대 등록수 배열 [100,600,200,100] 신설 |

### 3-2. 기본 시나리오 전환

| 항목 | v6.0 | v6.1 |
|---|---|---|
| M_clinics | 10 (파일럿) | **100** (복지부 시범사업안) |
| totalN | 69,604 | **100,000** |

파일럿 실측 데이터는 "파일럿 로드" 버튼(`loadPreset(presets[0])`)으로 즉시 전환 가능.

### 3-3. UI 재구성 (시연·모바일 최적화)

**문제의식**: v6 개발이 진행되면서 설명·수식 텍스트가 과도해지고, 슬라이더와 KPI가 물리적으로 떨어져 시연 시 "슬라이더 드래그 → 결과 변화"를 한 화면에서 볼 수 없게 됨. 특히 모바일 세로 화면에서 심각.

**해결**: 탭 레이아웃 전면 재구성, 설명·수식을 "공식 구조 토글"(맨 아래)에 집결, 핵심 입력·결과만 상시 노출.

수가 탭 새 순서:
1. 등록환자 규모 (접힘, 한 줄 요약)
2. P 4슬라이더
3. F 4슬라이더 (P와 동일 구조, 정책강도 슬라이더는 제거 — 최종안)
4. T = P + F (접힘)
5. L 변화율 (슬림 박스 — 제목 한 줄에 "현재 → 변화 후 · LC", 슬라이더만)
6. **KPI 2카드** (토글 제거, 상시 표시)
   - 의원당 평균 변화 **만원 단위** 확대
   - 기준선 / LC 후 의원당 수입 **상시 노출** (크게)
7. 차트 · Win-Win-Win
8. 📐 공식 구조 (맨 아래 토글) — 모든 수식·환자군별 L 상세 집결
9. ⚙️ 데이터 관리

Track 탭도 동일 패턴: Track 선택 → L 슬림 → KPI 상시 → PT 박스 → 차트·표.

Shared Saving 탭: 항목별 슬라이더(입력) → Shared Saving 총괄(결과) 순서로 정리.

### 3-4. Track 탭 PT 박스 (정보 표시)

노션 v2.7 부록 §3에 명시된 "일차의료 전환지원금"을 Track 탭에 정보 박스로 추가:

- 의원당 1년차 합계 = Track 수입 변화 + PT 명시
- 시뮬레이터 수식(의원 수입·공단 지출)과는 독립

### 3-5. 의원당 단위 명확화

- 전체 변화액: 억원 유지 (`diffAuto`)

## 4. 핵심 수식 (v6.1 이관용, 변경 금지)

```
P     = 환자군 기준의료비 × 의원급 외래비중         (빅데이터 산출)
T     = P + F                                     (명목 청구수가)
A     = P × (1 − L) + F                            (공단 실지급, F는 L 우회)
B     = M1 × 30%                                   (본인부담, 고정)
의원 수입 = 등록환자 (A + F + B)  +  비등록환자 (M1)

Track (1인당 등록환자 실지불액):
  tA = M1 + F                                     (FFS + F)
  tC = P × (1 − L_new) + F + M1 × 0.3              (환자군 모형 + F)
  tB = (tA + tC) / 2                              (혼합)
  tS = tA × ffsPct + tC × hccPct                   (선택)

PT (정보 표시 전용, 수식 영향 없음):
  PT = (hccPct / 100) × 30,000,000                 (의원당, 1회 · 첫해)
```

공단 서버 이관 시 위 수식을 SQL/스크립트로 이식하면 됨. `src/hooks/useSimulator.js`의 `G` useMemo 참조.

## 7. 개념적 주의 사항 (이관팀 · 후속 개발자용)

### ⚠ F는 add-on이 아니라 상대가치 재조정
F를 "행위별 수가 위에 얹는 추가 수당"으로 잘못 표현하면 안 됨. 노션 v2.7 §Ⅲ-2의 구조: F는 환자군 기반 지불 구조 내부에 내장되어 저평가된 일차의료 본연 기능의 상대가치를 보정. "add-on vs 재조정"의 구분이 보고서 핵심 메시지.

### ⚠ T ≠ A (명목 vs 실지급)
T = P + F는 **명목 청구수가**. 공단이 의원에 실제 주는 돈은 A = P × (1 − L) + F. L이 77% 수준이면 T와 A의 차이가 매우 크다. 이 구분을 놓치면 재정 추정이 틀어짐.

### ⚠ F는 L 우회
F는 "등록관리·상대가치 보정"이지 진료비 재배분이 아니므로 L에 걸리지 않음. Track A에서도 F 효과가 나타나는 근거이며, 노션 Q3 "수입 감소 없음"의 핵심.

### ⚠ 등록환자 분포는 추정치
`regDist` 기본 [100,600,200,100]은 실측 자료가 아닌 보고서 부록의 **추정치**. 시연 시 "임의 배정/추정치"임을 명시할 것. 실측 자료 확보 시 덮어쓸 것.

### ⚠ PT는 시뮬레이터 수식과 독립
PT(일차의료 전환지원금)는 Track 탭에 정보 박스로 표시되지만, 시뮬레이터의 의원 수입·공단 지출 계산에는 포함되지 않음. "1회성 첫해"라는 성격상 연간 흐름과 분리.

### ⚠ 복지부 공식안 단가 비율 1:1.65:2.37:2.95
F 공식안 [122860, 203040, 291120, 362530]은 이 비율로 고정. 중간 커밋(`6f4f0c6`)에서 "정책 강도 배수 슬라이더"로 전체 스케일 기능을 넣었다가 시연 단순화를 위해 최종 제거됨. 만약 다시 필요하면 해당 커밋 참조.

### ⚠ 기본 시나리오와 파일럿 데이터의 구분
- `initialState` = **복지부 시범사업안** (M=100, totalN=100,000, 100% 등록)
- `presets[0]` = **파일럿 실측** (M=10, totalN=69,604, L·M1 실측)
- "기본값 복귀" 버튼 → initialState, "파일럿 로드" 버튼 → presets[0]. 두 동작 의미 다름.
