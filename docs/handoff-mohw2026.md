## 1.5. v7.5 리포 대조 결과 (반영 완료 — 아래를 전제로 작업)

## 3. 복지부 엔진 스펙 (`mohw2026`) — 검증된 상수

> 아래 수가표는 Python으로 산술 정합성 검증 완료 (§5 테스트 케이스가 그 검증의 코드화). 상수는 그대로 하드코딩하되, **출처 주석**을 반드시 단다.

### 3-1. 분위별 연간 수가 (단위: 원/연, 50세 이상 추정 모집단)

```js
// 출처: 복지부 공고 제2026-562호 붙임1, 연간 수가(안)
// [1분위, 2분위, 3분위, 4분위]
const MOHW_FEE = {
  // ➊ 진료서비스 (통합수가제 선택 시)
  care_integrated:   [48507, 75581, 116838, 207273],
  // ➊ 진료서비스 (행위별수가제 선택 시) = 현행 FFS (별도 산출, 여기선 null 처리)
  care_ffs:          null,
  // ➋ 일차의료서비스 (통합수가제 선택 시) — 통합수가제는 30% 가산
  primary_integrated:[75959, 118356, 182963, 324579],
  // ➋ 일차의료서비스 (행위별수가제 선택 시)
  primary_ffs:       [58430, 91043, 140740, 249676],
};
// ➊+➋ 합계(통합수가제) = [124466, 193937, 299801, 531852]  (검증: 각 분위 care+primary와 일치)
```

**구조적 사실 (재현 로직에 반영, 비교 뷰에서 지적 근거로 사용):**
- 세 수가표의 분위 비율이 **1 : 1.558 : 2.409 : 4.273** 로 소수 셋째 자리까지 동일 → ➋는 독립 산정이 아니라 ➊의 HCC 위험도에 **단순 비례 배분**된 값. (공고문도 "비례적 반영" 명시)
- ➋ 통합수가제 ÷ 행위별수가제 = **정확히 1.300** (전 분위) → 통합수가제 전환 지원 30% 가산.

### 3-2. 공고문 산정식 (재현 뷰에 병기)

```
분위별 통합수가 = 환자 분위별 평균 예측 의료비 × 의원 외래 비중 × (1 − 유출률)
   유출률 = 등록환자의 타 의원 이용 비중
```

**[MODELING-DECISION-01] 유출률 처리 — 중요.**
공고문은 위 산정식만 제시하고 `평균 예측 의료비`·`의원 외래 비중`·`산정 시 가정한 유출률`을 **공표하지 않았다.** 따라서 §3-1 수가표에 유출률이 얼마로 내재됐는지 알 수 없다. 재현 뷰에서는:
- **기본값: 유출률 = 0** → §3-1 공고 수가표를 **그대로** 표시 (공식 공표치 재현).
- 유출률 슬라이더(0~1)는 **탐색용**으로 제공하되, `공단지급(탐색) = 공고수가 × (1 − 유출률)` 로 계산하고 아래 주석 필수:
  > 공고 수가표에 내재된 유출률은 미공개이므로, 이 슬라이더는 "유출률이 이 값이라면 공단지급이 어떻게 변하는가"를 보여주는 탐색용입니다. 공고 절대값과의 이중 차감이 아님.
- 이 미공개 사실 자체가 우리 연구의 지적 포인트다. 비교 뷰 §4 각주로 노출.

### 3-3. 운영지원·성과보상·제약 (단독모형 기준)

```js
const MOHW_PARAMS = {
  ageMin: 50,                 // 대상 연령 하한
  registerCap: 1000,          // 기관당 등록 상한
  opSupportSolo: 30_000_000,  // ➌ 운영지원 (단독모형, 전액 사전지급)
  // 성과보상 ➍: 기준액 = (➋일차의료서비스 + ➌운영지원). ➊진료서비스는 기준액에서 제외.
  perfCapRate: { integrated: 0.20, ffs: 0.10 },  // 상한 비율
  feeAdjustCycle: '1년',      // 수가 조정 주기
  payCycle: '월',             // 통합수가 지급 주기
};
```

- 성과보상 상한 = `(➋합계 + ➌운영지원) × perfCapRate`. 재현 뷰에서는 **상한액만** 표시(실제 성과금은 사후 평가라 산출 불가) + "상한이며 실지급은 절대평가 결과에 따름" 주석.
- 본인부담: 보상방식 무관 **현행 행위별수가 기준** 고정. ➋일차의료서비스는 **본인부담 없음**.
- 비급여는 통합수가 미포함.
- **기본 분위 분포**: 재현 뷰 진입 시 기본값 = `[201, 198, 294, 307]` (1,000명 기준, §1.5-3). 사용자 슬라이더 조정 가능하되 합계 1,000명 cap.

## 5. 검증 테스트 케이스 (vitest) — 필수

새 엔진에 대해 아래를 그대로 테스트로 구현. 값은 Python 검증 완료치.
(※ 아래 성과보상 테스트의 250 균등분포는 **산술검증용 fixture**일 뿐, 재현 뷰 UI 기본값이 아니다. UI 기본값은 `[201,198,294,307]` — §1.5-3.)

```js
// mohw2026.test.js
import { describe, it, expect } from 'vitest';
// import { mohwTotal, mohwPerfCap } from './mohw2026';

const care = [48507, 75581, 116838, 207273];
const p_int = [75959, 118356, 182963, 324579];
const p_ffs = [58430, 91043, 140740, 249676];
const total = [124466, 193937, 299801, 531852];

describe('복지부 수가표 정합성', () => {
  it('➊+➋(통합) = 공고 합계', () => {
    care.forEach((c, i) => expect(c + p_int[i]).toBe(total[i]));
  });
  it('분위 비율이 세 표에서 동일 (1:1.558:2.409:4.273)', () => {
    const ratio = arr => arr.map(x => +(x / arr[0]).toFixed(3));
    const expected = [1, 1.558, 2.409, 4.273];
    [care, p_int, p_ffs, total].forEach(arr =>
      expect(ratio(arr)).toEqual(expected));
  });
  it('➋ 통합/행위별 = 1.30', () => {
    p_int.forEach((v, i) => expect(+(v / p_ffs[i]).toFixed(2)).toBe(1.30));
  });
});
```

## 6. 표시 원칙 (통합참조 v6.5 §14 — 우리 모형 측에 적용)

1. **절대 수입값 미노출** (우리 모형): 의원 매출 ≠ 의사 소득. 토글로 숨겨도 금지(역추산 가능).
2. **변화율(%) 미노출**: 분모 역추산 방지. 트랙/모형 비교는 **시각적 막대만**.
3. **변화액(원) 단독** 표시 시 주석 필수: "본 사업 발생 변화분만. 비급여·기타 별도".
4. **명칭**: "수입 변화"(Win-Win-Win 주체). "의원 수입 강화" 문구 절대 금지 → "일차의료 지원".
5 복지부 공고 수가표 절대값 표시는 **허용**(공식 공표치 인용이므로). 이 원칙은 **우리 모형이 추론한 값**에만 적용된다.
