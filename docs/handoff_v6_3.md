## 1. 이번 릴리스 배경 (v6.2.3 → v6.3.0)

v6.2.x는 용어(B/F/P)·UI 가독성·패널 효과 분해에 집중. v6.3.0은 **데이터 입출력 층**에 집중한 릴리스:

1. **공단 분석 → 시뮬레이터 → 연구보고서** 연결 체인에서 엑셀 파일이 단일 source of truth가 되도록 템플릿 재설계.
2. 기존 `v7.xlsx` 참조 템플릿은 입력층·산출층 구분이 있었으나 (a) 시뮬레이터 파서와 헤더 불일치, (b) F=0 가정으로 보고서용 미흡, (c) 원자료(N·T·C·M) 투명성 부족.
3. 신규 v1 템플릿은 **원자료·파생·산출 3층을 단일 시트에 일렬 배치**, 수식 내장, F 포함 실질 제시값 출력.
4. 부수적으로 시뮬레이터의 `COL_ALIASES` 매칭 버그 1건(P 별칭 충돌) 발견·수정.

## 2. 주요 변경 (v6.2.3 → v6.3.0)

### 2-1. 신규 엑셀 템플릿 `NHIS_HCC_시뮬레이터_업로드_v1.xlsx`

**위치**: `docs/NHIS_HCC_시뮬레이터_업로드_v1.xlsx`
**재생성 스크립트**: `scripts/gen_upload_template.cjs` (파일럿 2023 값 기반)

**구조**: 단일 시트 `시뮬레이터_업로드` · 1행 헤더 · 2~5행 4군 데이터 · 6행 합계/가중평균 · 총 15열 3층

| 층 | 엑셀 열 | 이름 | 비고 |
|---|---|---|---|
| 라벨 | A | 환자군 | 1~4군 식별 |
| **원자료** | B~E | N · T · C · M | 분석가가 SQL에서 추출·붙여넣기 |
| **파생** (수식) | F~I | HCC 평균·의원비중·L·M1 | `=T/N`·`=C/T`·`=(C-M)/C`·`=M/N` |
| **산출** (수식) | J~O | B·F·P·공단지급·본인부담·1인당 의원수입 | `=ROUND(HCC×cr)` · 제시안 고정값 · `=B+F` · `=ROUND(B(1-L)+F)` · `=ROUND(M1×0.3)` · `=공단지급+본인부담` |

**분석가 입력 최소화**: 4 원자료 컬럼 × 4군 = **16 셀**만 입력. 나머지 자동 재계산.

**보고서 직결**: 산출층은 F 포함 실질 제시값 → 복사해 논문·연구보고서 테이블로 즉시 활용.

### 2-2. `COL_ALIASES` 재정비

**`src/constants.js`**:
- `ref`에 `"HCC 평균"`(공백 있음) 추가 — v1 템플릿 헤더와 매칭
- `P`에 `"B"`·`"환자군 기본수가"` 추가하고 순서를 `["B", "환자군 기본수가", "수가", ...]`로 재배치
- **⚠ `"P"` 별칭 제거**: v1 템플릿의 `P = B+F` 컬럼이 먼저 매칭되어 state.P에 B+F 값이 들어가는 버그 방지. 왕복(export→import) 일관성 유지 필수 조치
- `F` 신설: `["F", "일차의료 기능보정", "기능보정"]`

### 2-3. `handleFile` 파서 개선

**`src/hooks/useSimulator.js`**:
- F 파싱 추가: `findCol(row, COL_ALIASES.F, -1)` → `state.F_g`로 반영
- B 자동산출 fallback: 엑셀 B 컬럼 없으면 `ref × cr`로 계산 (구 로직은 `INIT_P` 고정값 fallback이었음)
- LOAD_DATA action에 `F_g` 전달
- 업로드 상세 배너에 `B=` · `F=` 값 추가 표시

### 2-4. `handleExport` 15열 전면 재작성

**`src/hooks/useSimulator.js`**:
- 7열 legacy 구조(`환자군·기준의료비·의원비중·환자수·현재외래비·타원이용비중·수가`) → 15열 3층 구조로 교체
- 원자료(N·T·C·M) 역산: `T = ref × N` · `C = T × cr` · `M = M1 × N`
- 파생·산출층 전체 수식으로 출력 (엑셀에서 열면 자동 재계산)
- 시트명 `시뮬레이터_출력` → **`시뮬레이터_업로드`** (업로드 자동 매칭 통일)
- 합계/가중평균 행 포함 (보고서 스타일)

### 2-5. Reducer `LOAD_DATA` 확장

**`src/hooks/useSimulator.js`**:

### 2-6. 기존 v7 참조파일 삭제

## 3. 핵심 수식 (v6.3 기준, v6.2.2와 동일)

변경 없음. 참조: [`docs/handoff_v6_2.md` §3](handoff_v6_2.md).

```
B      = HCC평균 × 의원비중       (환자군 기반 FFS 대체 수가)
F_g    = 일차의료 기능보정 (배열) (등록 관리 + 저평가된 본연 기능 보정)
P      = B + F                   (명목 청구수가)
공단지급 = B × (1 − L) + F        (F는 L 우회)
본인부담 = M1 × 30%               (고정)
```

엑셀 v1의 산출층 수식이 위 수식과 1:1 매핑.

## 8. 주의 사항 (이관팀 · 후속 개발자)

### ⚠ `COL_ALIASES.P`에 `"P"` 별칭 추가 금지
v1 템플릿에서 "P" 헤더는 B+F(일차의료수가)를 의미. 시뮬레이터 `state.P`는 내부적으로 B값을 담는 변수. 별칭에 "P"를 재추가하면 v1 업로드 시 state.P에 B+F 값이 들어가 왕복 깨짐.

### ⚠ 합계행은 앞 4행만 슬라이스되어 자동 제외
`handleFile`의 `data.slice(0, 4)`는 6행(합계)를 자동 배제. 보고서용 합계는 있어도 무해. 단, 환자군 데이터 행 순서가 1~4군 순이 아니면 매칭 깨짐.

### ⚠ 왕복 후 L 값이 원시와 약간 다를 수 있음
INIT_BASE의 L(0.7975)과 역산된 L`(C-M)/C`(0.776)이 불일치. 원인: INIT_BASE의 ref·cr·L·M1이 개별 측정값이라 정합성 미흡 (파일럿 10개 기관 근사치). 실측 데이터 업로드 시에는 N·T·C·M이 일관되므로 문제 없음.

### ⚠ 엑셀 수식 vs 캐시값
xlsx 라이브러리는 수식 재계산 안 함. 셀에 `{ f: '...', v: ... }` 둘 다 설정. v는 초기 캐시값. 엑셀에서 파일을 한 번 열었다 저장하면 v가 수식 결과로 갱신됨. 시뮬레이터는 v만 읽으므로 재계산 없는 파일도 OK.

### ⚠ F 열 선택적 파싱
v1 템플릿 F 열은 제시안 고정값. 시뮬레이터는 엑셀 F 값을 state.F_g에 반영하지만, 사용자가 UI에서 F 슬라이더 조정하면 덮어씀. 엑셀의 F는 "정책 제시안"일 뿐 시뮬레이터 유일 진실 아님.

### ⚠ v7 템플릿 역호환 없음
이전 v7 참조파일 삭제. 만약 공단 분석팀이 v7 양식으로 제출하면 시뮬레이터가 헤더 오프셋으로 파싱 실패함. 공단에 v1 템플릿 배포 필요.
