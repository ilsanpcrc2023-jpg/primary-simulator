## 작업 배경

v6.4.1에서 UI 폴리시가 끝난 뒤, 일차의료개발센터장 사용 시나리오를 따라가며:
1. **정책 해석 디폴트 정돈** — 참여 전·후 환자수, LC, PT 기준 금액의 기본값을 실제 발표 기본 시나리오에 맞춤.
2. **HCC 환자 위험군별 분석 결과 반영** — 환자군 기본수가 B 디폴트를 노션 「2A 표」 기반 실측 계산치로 갱신.
3. **L 변화율 표현력 확장** — 강한 외부유출 감소 시나리오까지 시뮬 가능하도록 슬라이더 도달 범위 확대.
4. **F 액션 버튼 UX 재설계** — 덮어쓰기 방식 → 누적 증가 방식으로, 사용자가 입력한 값을 보존.
5. **P 카드 헤더 정보 통합** — L 반영이라는 핵심 개념을 동적 % 값과 함께 헤더에 노출하고, 중복되던 하단 수식 블록 제거.

도메인 수식·엑셀 포맷은 v6.4.0 그대로. 정책 기호(B·F·P·공단지급·본인부담) 변화 없음.

### v6.4.6 (F 버튼 1차 재설계: 디폴트값 + 끝자리 보정 누적)

**커밋**: `c70e635` → merge `7065c89`

- 균등 버튼: 1군 값 복사 → **4군 모두 20,000원 고정**
- 차등 버튼: 1군 값 기준 1:2:3:4 → **`[10000, 20000, 30000, 40000]` 고정** (1·2·3·4만원)
- 끝자리 보정 버튼: 덮어쓰기 → **누적 방식**
  - `F_new = F_old + (ceil(B/10000)×10000 − B)`
  - 기존 F 값 보존하면서 P가 만원 단위로 떨어지도록 정돈
  - F=0이면 종전 동작과 동일 (보정값만 들어감)
  - B가 이미 만원 배수면 diff=0이라 F 변화 없음

### v6.4.7 (F 버튼 2차 재설계: 누적 증가)

**커밋**: `a10da3b` → merge `9db5c52`

사용자 요청으로 균등/차등을 고정 디폴트에서 **누를 때마다 1군 기준 1만원씩 상승**하는 방식으로 변경.

- 균등: `const v = F_g[0] + 10000; setFAll([v, v, v, v])` — 매 클릭 1군 +1만원 → 4군 동일 값
- 차등: `const v = F_g[0] + 10000; setFAll([v, v*2, v*3, v*4])` — 매 클릭 1군 +1만원, 2·3·4군은 배수
- **검증 시퀀스** (초기 F=[10,20,30,40k]):
  - 균등×1 → 20/20/20/20k
  - 균등×2 → 30/30/30/30k
  - 차등×1 (균등×2 후) → 40/80/120/160k
  - 차등×2 → 50/100/150/200k

### v6.4.8 (P카드 헤더 동적 L% + 하단 수식 블록 제거)

**커밋**: `b5ab74f` → merge `d757127`

- 헤더 변경:
  - 이전: `일차의료수가 (P = B + F)` + 우측 설명 `명목 청구수가 · 공단 실지급액 ≠ P`
  - 현재: `일차의료수가 (P = B + F) → 타원이용비중 (78.6%) 반영 후 공단 지급` (제목 옆 이어 배치)
  - 78.6%는 **LavgAfter 기반 동적 계산** — LC 슬라이더 조작 시 실시간 갱신 (예: LC=-10%p → 68.6%)
- TCard 내부에서 `Lavg = Σ (N_i/totalN) × L_i`, `LavgAfter = clamp(Lavg + LC/100)` 계산 (TabSimulation과 동일 공식).
- 하단 `공단지급 = B×(1−L) + F` + `의원 수입 = 공단지급 + 본인부담` 설명 블록 제거 — 동일 내용이 페이지 하단 `📐 수가 산출 구조` 아코디언에 이미 존재.

## 프로세스 메모 (이번 세션에서 합의된 운영 규칙)

### ✅ 세션 시작 시 `git pull` 필수
- 세션 개시 지시("CLONE", "시작", "대기")를 받으면 CLAUDE.md/인계장 읽기 전에 먼저 `git fetch && git pull`.
- `git status`의 "up to date" 메시지는 stale 추적 정보 기준이므로 fetch 없이는 원격 변경을 못 봄.
- 2026-04-21 세션에서 v6.2.0 기준으로 작업하다 원격 v6.4.1 발견 후 reset·rebase로 수습한 사고 재발 방지.
- 메모리: `feedback_session_start_pull.md`.

### ✅ 머지는 사용자 명시 지시 시에만
- 변경 후 프리뷰 검증이 끝나도 자동으로 머지하지 않음. "머지" 지시 대기.
- 사용자가 여러 미세 변경을 한 묶음으로 머지할지 판단하고 싶어하므로 자동화 금지.
