## 1. 변경 배경

### 1.1 정치 리스크 차단 (1차 작업)

> "시뮬레이터의 의원 총수입 절대값(예: 104,292만원, 108,410만원)과 변화율(%) 노출이 정치적 리스크를 만든다. 시민단체·언론이 절대 매출액을 의사 개인 소득으로 왜곡 보도할 위험, 변화율(%)에서 분모를 역추산해 절대 수입을 복원할 수 있는 위험이 있다. 화면 표시를 절대 변화액(원)만으로 단일화한다."

핵심 결정:
- 모든 화면에서 **의원당 절대 수입값 노출 금지** (104,292만원·108,410만원·109,011만원·104,298만원·108,272만원·108,973만원·109,774만원·111,796만원·126,710만원·145,248만원 등)
- **변화율(%) 텍스트 전면 제거** — Track 우위 비교는 색상·폰트로만
- **변화액(원)만 단일 표시** — "+4,719만원/년" 형식
- "포괄관리 성과가산"이라는 라벨이 길고 위계 모호 → "포괄관리성과 가산금"으로 분리하라는 1차 요구는 이후 "포괄관리성과"로 단순화 (작업 C 단계에서 사용자 재결정)

### 1.2 Shared Saving Track 가산 분리

> "C축(Shared Saving)은 시범사업 1-2년 종단 데이터 필요. 사전 Track 가산 약속은 신뢰도 리스크. B축(즉시 측정 가능)만 Track 연동 유지."

→ `tracks.ongoing` 합산에서 SS 제외, Track 비교 화면에서 SS 항목 제거, Shared Saving 탭은 "참고 시나리오"로 전환.

### 1.3 의원 모드 = 정책 모드와 차별 (5번 작업)

> "수가 시뮬레이션 의원모드에서는 정책모드와 차별화. 고로 분해 추가 노출하지 말것"

→ 의원 모드는 KPI Hero 단독, 정책 모드는 분해(①②③) 별도 유지하되 KPI Hero 1차 통합.

### 1.4 의원 모드 진정한 단순화 (4번 작업 후 추가 지시)

> "의원모드도 정책모드에 준해서 수치 공식이나 필요없는 설명 삭제"

→ 의원 모드에서 ClinicCountCard / Track 비교 박스 / 데이터 관리 박스 모두 정책 모드 전용으로 후퇴.

### 1.5 포괄관리 지표 C = 1 − L2 (새 차원)

> "L1(타원이용비중)은 미국 PCF 기반의 환자군 구조 지표로 유지. 포괄관리 지표는 새 개념이므로 C(Comprehensiveness, 1−L2)로 도입. L1은 구조 특성, C는 성과 차원 — 다른 각도의 두 지표."

핵심:
- L1 카드 헤더 "선지급 기준 타원이용비중(L1)" → "평균 타원이용비중(L1)"
- L2 카드 → C 카드로 전환 (헤더 "포괄관리 지표 (C)", 부제 "등록의원의 외래 진료비 비중 (C = 1 − L2)")
- 슬라이더 음수(-25~0%p) → 양수(0~+25%p)
- 가산 공식: `포괄관리성과 = max(0, C − (1 − L1)) = max(0, L1 − L2)` (등치)
- 내부 계산은 L1·L2 absolute 그대로 유지, C는 표시 파생 변수

### 1.6 모드 토글 위치 이동 (마지막 작업)

> "현재 최상위 토글이지만 영향은 수가 시뮬레이션 탭에만 미침. Track·성과배분 탭에서는 토글이 작동 안 해 인지 불일치 발생."

→ 헤더 토글 제거, 수가 시뮬레이션 탭 상단(안내 박스 아래)에 "관점 선택" 라벨로 재배치. Track·성과 배분 탭은 토글 미노출.

**수가 산출 구조 공식 박스**:
```

포괄관리성과 = max(0, C − (1 − L1)) = max(0, L1 − L2)
```

### 2.7 KPI Track 비교 일치 (6만원 차이 해소)

**기존 차이 원인**:
- 수가 시뮬 KPI: `baseN_per_clinic × ffsPerPerson × M` (디폴트 6960명/의원)
- Track 비교: `T.inc0 / M` (totalN/M = 6960.4명)
- 4명 차이 × 가중평균 ≈ 6만원

**해결**: useSimulator tracks 메모에 `netChange = ongoing − decomp.baselineIncome/M` 추가:
```js
const tracks = useMemo(() => {
  const baselinePerClinic = (decomp?.baselineIncome ?? 0) / M;
  // ...
  return list.map(t => {
    const ongoing = t.income + perfAmt;
    return { ..., ongoing, netChange: ongoing - baselinePerClinic };
  });
}, [..., decomp.baselineIncome]);
```

활성 Track의 `netChange`가 정확히 `perClinicNet`(수가 시뮬 KPI)와 일치 (예: +4,719만원).

## 5. 알려진 제한

- **포괄관리성과 등치**: UI는 C=1−L2 양수 슬라이더로 표시하지만 내부 산식은 `max(0, L1 − L2)` 그대로. 두 표현이 수학적으로 동일하다는 것을 사용자 안내문에서 명시.
- **사업 참여 의원 수 박스**: 정책 모드에서만 노출. 의원 모드에서는 의원 1개 시뮬 관점이라 불필요. 하지만 Hero KPI의 "전체 사업 합계" 표기는 여전히 M_clinics 사용 — 데이터 변경 시 의원 모드에서 의도 외 동작 가능 (현재 디폴트 10개 고정).
- **Shared Saving 시연 로직 보존**: ssPctA/B/C state는 유지(reducer/state 무변경), UI 편집만 제거. 미래 도입 시 박스 부활 또는 제거 결정 필요.
- **포괄관리성과 박스 폐지**: Track 탭에서 박스 자체 삭제. 사용자 진단·확인 용도가 필요하면 부활 검토.
