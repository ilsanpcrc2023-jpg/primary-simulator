# v6.8 Phase 2 인계장 — 의원 모드 추가 개선

**생성일**: 2026-04-25
**대상 버전**: v6.8.2 (또는 v6.9)
**선행 커밋**: v6.8.1 (용어 재편 + 의원 모드 단순화) — 이 커밋 기반으로 진행

## 배경

v6.8.1 커밋에서 사용자 지시서의 1~4번 + 6번(용어 치환, 모드 토글 재디자인, 첫 진입 변경, 의원 모드 단순화)을 완료했다. 5번(Phase 2)은 신규 UI 컴포넌트·state 추가가 필요해 별도 세션으로 분리.

원 지시서 5번 항목은 다음 두 가지:

### 5.1 의원 프리셋 버튼
환자군 패널 상단에 다음 5개 버튼 추가:
```
[일반 의원] [만성질환 특화] [노인 집중] [신도시 의원] [사용자 지정]
```
각 버튼 클릭 시 **환자군 구성(1:2:3:4군 비율)** 과 **등록환자수**를 해당 프리셋으로 설정.

### 5.2 Track별 간이 비교 카드
Track 탭에만 있는 Track A/B/C 수입 비교를 의원 모드 수가 시뮬레이션 탭 **하단에 요약 3카드**로 추가:
```
[Track A 유지]   47,241만원/년 (+5.1%)
[Track B 혼합]   49,273만원/년 (+9.6%)
[Track C 환자군] 51,305만원/년 (+14.1%)  ← 현재 선택
```

## 5.1 구현 지침

### 프리셋 값 (시안 — 센터장 확인 필요)

| 프리셋 | regDist(1:2:3:4) | n_reg 합 | 근거 |
|---|---|---|---|
| 일반 의원 (디폴트) | [100, 600, 200, 100] | 1,000 | 부록 기본 |
| 만성질환 특화 | [50, 300, 400, 250] | 1,000 | 2·3·4군 비중↑ |
| 노인 집중 | [30, 200, 400, 370] | 1,000 | 고령·고위험 |
| 신도시 의원 | [300, 600, 80, 20] | 1,000 | 건강한 젊은층 |
| 사용자 지정 | — | — | 현재 값 유지, 강조 해제 |

※ 등록환자수 합은 프리셋마다 달라도 되나, 디폴트는 1,000명으로 통일하고 상단 "등록 환자" NumBox로 총량 스케일 조정.

### 파일 수정 위치

- **[src/constants.js](src/constants.js)**: `CLINIC_PRESETS` 배열 export 추가
  ```js
  export const CLINIC_PRESETS = [
    { key: "general",   label: "일반 의원",     regDist: [100, 600, 200, 100] },
    { key: "chronic",   label: "만성질환 특화", regDist: [50, 300, 400, 250] },
    { key: "elderly",   label: "노인 집중",     regDist: [30, 200, 400, 370] },
    { key: "newtown",   label: "신도시 의원",   regDist: [300, 600, 80, 20] },
    { key: "custom",    label: "사용자 지정",   regDist: null },
  ];
  ```
- **[src/components/RegistrationPanel.jsx](src/components/RegistrationPanel.jsx)** `RegScaleCard`: 상단에 프리셋 5버튼 그룹 추가
  - 각 버튼 onClick: `setRegDistAll(preset.regDist)`
  - 활성 판정: `state.regDist`가 프리셋과 일치하면 하이라이트(파란 배경)
  - "사용자 지정"은 어떤 프리셋과도 불일치할 때 자동 활성

### 기존 기능 보존

- `setRegDistAll` 함수는 이미 [useSimulator.js](src/hooks/useSimulator.js)에 존재 — 그대로 재사용
- 기존 "등록 분포 프리셋"(부록/균등/건강편중/고위험편중, 데이터 관리 카드 내)과 **중복되지 않게 주의**:
  - 기존 것은 "개발자용·상세 조정용"으로 현 위치 유지
  - 신규 것은 "의원 운영자용·직관적 이름"으로 RegScaleCard 상단에 배치
- 의원 모드일 때만 상단 프리셋 노출, 정책 모드는 기존 구조 유지 (`mode` prop 활용)

## 5.2 구현 지침

### 배치
의원 모드 수가 시뮬레이션 탭의 **Win-Win-Win 카드 직전 또는 직후**에 신규 카드 삽입.
(Win-Win-Win은 v6.8.1 현재도 의원 모드에서 노출 중)

### 계산 소스
`TabTrack.jsx`의 `tracks` 배열을 재사용하는 게 가장 안전. `useSimulator`의 `tAchg / tBchg / tCchg`·`performance` 메모로부터 이미 계산됨.

**옵션 A (권장)**: Track 비교 로직을 [useSimulator.js](src/hooks/useSimulator.js)로 올려 메모화 후, `TabSimulation`과 `TabTrack` 양쪽에서 같은 `tracks` 배열을 재사용
  - 장점: 단일 소스 오브 트루스, 중복 방지
  - 주의: `TabTrack.jsx:27~55` 근처의 `tracks` 계산 블록을 통째로 훅으로 이동

**옵션 B (빠른 구현)**: `TabSimulation`에서 `tAchg / tBchg / tCchg`와 `perfPerClinicFull` 만으로 간이 추정
  - 단점: Track 탭과 숫자 미묘하게 불일치 가능 (PT·SS·성과가산 포함/제외 정책)

### 표시 형식 (시안)
```
📊 Track별 2년차 이후 연간 수입 (의원당, 단일 선택 시나리오)
┌────────────────┬────────────────┬────────────────┐
│ Track A 유지   │ Track B 혼합   │ Track C 환자군 │
│ 47,241만원/년  │ 49,273만원/년  │ 51,305만원/년  │ ← 현재 선택
│ (+5.1%)        │ (+9.6%)        │ (+14.1%)       │
└────────────────┴────────────────┴────────────────┘
→ Track을 변경하려면 Track 탭에서 선택
```
- 현재 선택된 Track에 강조 테두리(indigo) + "✓ 현재 선택" 뱃지
- 카드 클릭 시 Track 탭으로 이동(선택적 · 혼란 방지 위해 처음엔 제외 권장)

### 기존 기능 보존

- Track 탭의 `Track별 수입 비교` 테이블은 **절대 삭제하지 말 것** (이 카드는 요약 · 테이블은 상세)
- 계산 로직 변경 금지 — 표시만 추가
- 정책 모드는 이 카드 없이 기존 구조 유지
